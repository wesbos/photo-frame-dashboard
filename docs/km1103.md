# KM1103 Frameo frame (Harmony / ZhiHeXing, RK3126, Android 6.0.1)

Record of one unit, started 2026-11-04, macOS host. Observations are kept separate from guesses.
Unique identifiers (serial, MAC, IP) are left out, and so are the dumps; the owner keeps them outside
the repo. Retail name and where it was bought are not recorded.

Same vendor build line as the [Rollei Smart Frame WiFi 107](rollei-smartframe-107.md)
(`F6010T_ZhiHeXing_1010-…`), built about three and a half months earlier, under the brand and device
name `KM1103`. The two match in SoC, Wi-Fi module, WebView and the partition layout up to `userdata`,
and the Rollei 107 steps (ADB, root, backup, disabling the updaters) worked here as written. The eMMC
is smaller and the boot images differ.

### Partition table

The `mtdparts` table on the kernel command line is identical to the
[Rollei 107's](rollei-smartframe-107.md#partition-table-emmc-mmcblk0-512-byte-sectors), so the
partition starts are the same and `userdata` starts at eMMC sector 2,842,624. Only the eMMC size
differs (30,310,400 sectors here).

## Backup (2026-11-04, verified)

eMMC sectors 0-2,842,624 (everything before `userdata`), 1,455,423,488 bytes raw, the same length as
the Rollei 107 backup. Streamed with

```sh
adb exec-out "su -c 'dd if=/dev/block/mmcblk0 bs=512 count=2842624'"
```

in 3 min 45 s. The SHA-256 of the raw stream equals the hash of the gzip read back. No 512-byte
sector is entirely `0xCC`. 11 partitions were re-read on their own and matched the backup.
`userdata` was not backed up.

| Image | SHA-256 (whole partition, padding included) |
| --- | --- |
| `boot` (p5) | `c188c8e9a26e4a4623a3156e25a9d2c02f58b18f4e3357db0af9a48613b48ea2` |
| `recovery` (p6) | `39de83cd70167b2c38427cf5bbb0373018dda3521d60d0c608f7de4aedd555bf` |
| `kernel` (p4) | `6bf18728dd6c55431ce522fb76c42e692b2c83ddf58625e8d80d24592bf37b1b` |

All three differ from the Rollei 107's, so don't swap images between the two frames.

Restoring would need Rockchip loader mode; it has not been tried on this unit.

### Kiosk with the bundled dashboard

The dashboard was built from `dashboard/` (`npm run build`) and bundled into the APK with
`KIOSK_SITE=dist`, using the saved URL `http://127.0.0.1:8765/` as described in
[the kiosk README](../dashboard/kiosk/README.md#a-page-bundled-in-the-apk-no-server). It rendered
with the frame offline.

As on the Rollei 107, Android 6 has no `cmd package set-home-activity`. `--ez home true` turned on the
`.Home` alias, and once Frameo was disabled the kiosk was the only Home app, so Android chose it
without a chooser. No preferred Home activity is saved. If Frameo is re-enabled, expect a chooser at
the next Home press.

### Wait for `package-restrictions.xml` before rebooting

After `pm disable`, Android wrote `/data/system/users/0/package-restrictions.xml` several seconds
later, not at once. A reboot before the write can lose the change. Wait for the file to show the new
state (or about 30 seconds) before rebooting. The kiosk README's
[Start at boot](../dashboard/kiosk/README.md#start-at-boot) section has the same warning for the
Home alias and `pm disable-user`.

## Security notes for the owner

- `su` gives root with no prompt, so any app installed on this frame can take root. Install nothing
  untrusted.
- Android 6.0.1 and SELinux permissive. Put the frame on a guest or IoT network when it goes online.
- Anyone with physical access and a USB-A to USB-C cable gets root, with no prompt on the screen.
- The disabled updaters come back if they are re-enabled or the frame is factory reset.
- Keep the key that signed the kiosk APK: `adb install -r` of an update needs the same key.

## Host note

The kiosk README asks for JDK 17, build-tools 34.0.0 and platform 34. This unit's kiosk was built
with JDK 24 and build-tools 36.1.0 (`BUILD_TOOLS=$ANDROID_HOME/build-tools/36.1.0`). `build.sh` always
reads `platforms/android-34/android.jar`, so the android-36 `android.jar` was put at that path. The
APK installed and ran on this Android 6 frame. With build-tools 34, a newer JDK makes `d8` crash (see
the [Rollei 107 host note](rollei-smartframe-107.md#host-note)).
