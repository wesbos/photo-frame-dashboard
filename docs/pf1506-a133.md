# PF1506 AiMOR / Allwinner A133: access and recovery notes

The reports collected in [#104](https://github.com/wesbos/photo-frame-dashboard/issues/104),
[#118](https://github.com/wesbos/photo-frame-dashboard/issues/118) and
[OdyNobody's #186](https://github.com/wesbos/photo-frame-dashboard/pull/186) concern PF1506 frames
with AiMOR 6.0.70 and firmware `YHK.F-null-A133-1506-D2048-PF1506-V45-OS-KXW.0.20250813`.
They are owner observations, not proof that every PF1506 has the same hardware or behavior.

## Identity reported in #186

| Field | Observation |
| --- | --- |
| SoC / board | Allwinner A133, `sun50iw10p1`, `ceres-c3` |
| Fingerprint | `Allwinner/ceres_c3/ceres-c3:10/QP1A.191105.004/12:user/test-keys` |
| Android / kernel | Android 10, patch 2021-01-05, Linux 4.9.170 arm64 |
| Userspace | 32-bit, despite the 64-bit kernel |
| RAM / storage | 2 GB / 32 GB; encrypted f2fs data partition named `UDISK` |
| Display / touch | 1920×1080; `gslX680` reports a rotated 1280×800 touch grid |
| Ports / controls | USB-C device port, USB-A host port, power button; no volume keys |
| Root | Shipped `su 0`; shell itself is UID 2000; permissive SELinux reported |

The A33 PF1007L routes and LOOFII `scripts/a133/` partition procedures do not apply just because
the frame uses an Allwinner chip. Derive identity and layout from the actual unit.

## Stock access reports

In #104, two units reached the factory test app with an empty `license.properties` on removable
storage and five taps at the top-left. Its **is closed → is open** switch exposed USB ADB.
See the issue for those units' observations; this is distinct from a universal test-app password.

On #186's unit, the owner used the touchscreen to reach native Settings:

1. In AiMOR's Wi-Fi setup, type harmless sample text in the password field and select it.
2. Choose **Share**. Bluetooth crashed and its error dialog offered **App info**.
3. Open App info, then search Android Settings for **build number**. Seven taps enabled
   Developer options, where USB debugging and Rooted debugging could be enabled.
4. USB ADB appeared; `su 0 id` returned root. No host authorization prompt was reported.

Do not use a real password as the shared sample text. Keep crash dialogs enabled: hiding them
removes this escape route. To undo USB debugging, turn it off in Developer options only when
deliberately giving up that access. Network-key rejection was not established; keep root access
away from untrusted networks.

## Preserve the way back

On stock firmware, changing Home can leave the **LOVE IS SHARING** boot animation over the
screen until AiMOR's NavigationActivity starts (#104). One owner lost usable access after changing
Home and has no working USB connection (#118). **That recovery remains unsolved.** A different
unit's successful setup does not establish a rescue procedure.

Keep AiMOR available, prove Home and Settings → Apps by hand, and verify persistent independent
ADB before changing or disabling the current launcher. [PR #263](https://github.com/wesbos/photo-frame-dashboard/pull/263)
reports booting a kiosk while retaining AiMOR as Home on older `20250731` firmware; its code remains
under review and is not a fix for the locked-out `20250813` unit.

## Historical GSI result, not a flashing procedure

#186 reports LineageOS 20 / Android 13 running on one unit, with a device-specific touch mapping
and a separate custom kiosk. The 4.9 kernel's missing newer eBPF support was a concern for later
Android GSIs; no general upgrade compatibility is established.

The reported backup omitted `UDISK` and unreadable `frp`, and does not meet the full-device
backup rule. Restoration was not tested. The proposed fastboot commands did not enforce target
identity, original-content comparison or readback, so they are not reproduced here. The custom
kiosk and flashing toolkit remain in the contributor's project. A focused follow-up with a
guarded, device-specific procedure and verified undo can be reviewed separately.
